# v0.1.0-rc.16 Windows ARM64 qualification

**Verdict: failed.** On 2026-10-09, the published artifacts, offline prerequisites,
installation and Windows-local login passed on the retained development VM. The
first live coding request failed with `event_body_limit`; the runner stopped
without retry. Subsequent lifecycle acceptance remains unmeasured. This does not close
[#105](https://github.com/kreuzhofer/tofa-launcher/issues/105).

## Actual-candidate attempt and failure

The maintainer entered credentials locally in an interactive PowerShell window.
The unmodified pinned runner used the downloaded published assets and a new
owned state directory. Preflight, isolated recovery setup, asset verification,
install/repeat install, first-use login and fresh-process command discovery
passed. Credential backend was Windows Credential Manager (`keyring`). No secret
was entered in chat, copied from macOS, or exported into evidence.

The [original lifecycle report](../testing/evidence/rc16-windows-lifecycle-01-2026-10-09.json)
started at `2026-10-09T09:05:20Z`; the controller finished with exit 1 at
`2026-10-09T09:06:43Z`. Its first coding turn exited 1 after about 4.10 seconds:
upstream HTTP 200, then `stage=stream_read`, `failure=event_body_limit`, no text
or tool deltas observed, no completed response, no successful tools and no
expected output file. Guardian checks were not reached. The owned native
session was removed and native config/auth preservation passed.

The pinned observer raises this category when the SSE event accumulator or
pending line exceeds 256 KiB. The report does not retain the event type, exact
size or payload. It therefore cannot distinguish oversized provider output,
framing behavior or an observer defect. The offline limit regressions passed;
they do not reproduce the unknown live payload. No product or runner bytes
were changed and no live diagnostic retry was attempted.

The runner stopped before uninstall-preserving-login, reinstall, saved-login
reuse, repeat uninstall and its normal purge stage. Those acceptance checks
remain **unmeasured**. Its original cleanup flags accurately show the state left
at failure; that report is retained unchanged.

an ordinary interactive PowerShell controller using process-only `Bypass`.
This records the invocation, **not permission to rerun**. The report and state
paths now exist; keep them and the failed evidence. PATH selected the same
