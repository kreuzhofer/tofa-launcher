live main/Guardian checks, uninstall preserving login, reinstall/saved-login
reuse, repeat uninstall, and isolated purge/recovery remain **unmeasured**.
No candidate lifecycle state or credentials were created. Only the normal
Windows tofa config/credential file presence and relevant environment-variable

The retained VM was not marked disposable and CI was not impersonated. The

modified. The native fixture measured config/auth preservation and owned-session
cleanup; this does not substitute for the remaining lifecycle preservation checks.
The pre-existing `skills-lock.json` modification retains SHA-256

Once the maintainer can enter credentials locally, run the pinned runner in an
ordinary interactive PowerShell terminal. This uses the already downloaded
verified assets, a **new** owned state directory, and the explicitly tested
0.160.1 client. Prefixing PATH selects the same client for onboarding; `--codex`
selects it for live checks. Never put API keys in the command or chat.

```powershell
$qualificationRoot = Join-Path (Get-Location) '.qualification/windows-local/issue-105-rc16'
$qualificationCodex = Join-Path $env:USERPROFILE '.codex/packages/standalone/releases/0.160.1-aarch64-pc-windows-msvc/bin/codex.exe'
$env:PATH = (Split-Path $qualificationCodex) + ';' + $env:PATH
$env:TOFA_NATIVE_WINDOWS_CODEX_HOME = Join-Path $env:USERPROFILE '.codex'
python "$qualificationRoot/source/scripts/qualify_windows.py" `
  --version v0.1.0-rc.16 `
  --downloaded-assets "$qualificationRoot/assets" `
  --agent-state-root "$qualificationRoot/lifecycle-01" `
  --output "$qualificationRoot/lifecycle-01.json" `
  --codex $qualificationCodex --check-pair `
  --model deepseek-ai/DeepSeek-V4.1-Flash `
  --guardian-model zai-org/GLM-5.3-Flash
```

Run from the repository root. The runner prompts for Windows-local login and
automates only its owned lifecycle/purge. On failure, retain the report, inspect
remaining owned state, and stop before any paid rerun. Do not reuse existing
