Both installers resolve the latest stable release when the version argument is
omitted. Resolution happens once; binary and checksum downloads use that exact
tag. Invalid, unavailable or prerelease resolution fails explicitly. Explicit
versions remain available for prereleases and rollback. Permanent installer URLs
and no-version commands are documented in the README.

The publishing workflow now accepts stable tags and marks a stable release Latest
only after all native checks, complete-manifest verification, uploaded/downloaded
byte comparison and source-tag identity checks pass. Prereleases stay out of
Latest. This candidate is a prerelease; no stable publication was requested.

## Validation

- The shell prerelease-rejection test failed against the previous resolver, then
  passed with validation. Stable-publication tests first failed because the old
  publisher rejected stable tags, then passed. All 5 latest shell cases, 2 existing
  installer cases, 8 publication cases and Go workflow tests pass.
- Local macOS 26.7 (25G229), ARM64, Go 1.27.1: `go vet ./...` and
  `go test -race ./...` pass. Four lifecycle cases and two terminal cases pass
  against the exact canonical rc16 binary and bundled installer, using disposable
  synthetic state. Install/repeat/reinstall, preserve-uninstall, purge, corrupted
  downloads and recovery retain their existing contracts.
- The actual rc16 Mac binary also installs with no version argument through a
  controlled stable redirect. The fixture would move its latest response on a
  second lookup; the installer makes one lookup and two pinned downloads.
  Installed bytes equal the checked binary, `tofa --version` reports rc16 and
  synthetic settings are unchanged. This is controlled transport evidence, not
  proof of a public stable release.
- Against the real public GitHub latest endpoint before any stable release exists,
  the bundled shell installer rejects the response and preserves an existing
  synthetic installation and settings. This verifies the current unavailable
  channel behavior, not a successful stable installation.
- Native CI on macOS ARM64, Linux amd64 and Windows amd64: all required jobs pass, including publication.
  The new PowerShell cases include moving latest, explicit version, malformed
  metadata, unavailable latest, failed download and checksum mismatch, with
  byte-for-byte saved-settings preservation. Native Windows execution was first
  observed in CI; no Windows red run is claimed.
- Standards review found no actionable issues. Spec review identified missing
  settings-preservation assertions; both platform suites now seed their actual
  isolated configuration location and assert preserved bytes on failures.
  Focused re-review found no remaining issues.
- Publication verification: all 17 checksummed assets plus `SHA256SUMS` match the canonical checked bundle; the remote tag matches the recorded source commit.
